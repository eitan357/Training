# היסטוריה: הגרסה הקודמת (Google Sheets + Apps Script) וכלי ההגירה

**קובצי מקור:** `javascript.gs` (464 שורות), `Index.html` (1,696 שורות), `Edit.html` (279 שורות) — כולם בשורש הפרויקט (לא בתיקיית `public/`), ו-`public/migrate.html` (כלי ההגירה הפעיל).

## מטרת המסמך

תיעוד זה **אינו מתאר פיצ'ר פעיל שיש להמשיך לפתח** — הוא הקשר היסטורי הנחוץ להבנת שני דברים: (1) מדוע קיים כלי הגירה בתוך המוצר החי, ו-(2) מדוע ברירות המחדל של משתמש חדש (`01-auth-onboarding.md`) נראות כפי שהן — הן הועתקו כמעט מילה-במילה מהגרסה הזו.

## מהי הגרסה הישנה

אפליקציית ווב שרצה כ-Google Apps Script Web App (`doGet`), עם Google Sheets כבסיס הנתונים היחיד. **אין בה מנגנון התחברות משתמשים כלל** — היא משויכת לחשבון Google היחיד שמריץ אותה (single-tenant, לא multi-user). הניתוב הפנימי פשוט: פרמטר `?page=edit` בכתובת מציג את `Edit.html` (עריכת תבניות), אחרת `Index.html` (המסך הראשי).

### מבנה הנתונים בגיליונות (Sheets)
- `TrainingTypes` — תבניות תרגיל (סוג, שם, יעד, מזהה) — מקביל ל-`users/{uid}/config/templates` בגרסה החדשה.
- `אימונים` — היסטוריית אימונים.
- `מדידות` — היסטוריית מדידות, עם **עמודה דינמית לכל סוג מדידה** (נוספת אוטומטית כשמגדירים סוג חדש).
- `סוגי מדידה` — הגדרת סוגי המדידה.

תבניות ברירת המחדל (8 תרגילי A, 8 תרגילי B, 8 סוגי מדידה) **זהות** לאלו שנוצרות היום למשתמש Firebase חדש (`initNewUser` ב-`public/index.html`) — הועתקו ישירות מה-Apps Script המקורי (`_insertDefaultTemplates`, `_insertDefaultMeasureTypes`).

### פעולות נתמכות (parity עם הגרסה החדשה)
מחיקת שורת תרגיל בודדת, מחיקת אימון שלם, עדכון אימון קיים (כולל מחיקת תרגילים בתוכו), מחיקת מדידה, שמירת תבניות/סוגי מדידה — כל אלו קיימים במקבילה מלאה בגרסת Firebase, פשוט מיושמים כפעולות על שורות בגיליון (`sheet.deleteRow`, `sheet.appendRow`) במקום מסמכי Firestore.

## מדוע הוחלפה

הסבה מלאה ל-Firebase (Auth + Firestore) מאפשרת: (א) ריבוי משתמשים אמיתי במקום תלות בחשבון Google Sheets יחיד, (ב) ביצועים טובים משמעותית (קריאת Firestore מהירה בהרבה מ-Apps Script שמריץ בכל בקשה קוד שרת שמבצע פעולות על גיליון), ו-(ג) בסיס לאפליקציית Android (Capacitor דורשת אתר סטטי מודרני — לא ניתן לעטוף Apps Script Web App באותו אופן, ראו `11-android-app.md`).

## כלי ההגירה (`public/migrate.html`)

כלי חד-פעמי, נפרד לגמרי מהאפליקציה הראשית (עמוד HTML עצמאי, לא חלק מ-`#sec-*`), עם תהליך תלת-שלבי ידני:
1. **ייצוא:** המשתמש מדביק פונקציית `exportData()` (מסופקת בתוך הכלי כקוד להעתקה) לתוך פרויקט ה-Apps Script הישן ומריץ אותה ידנית — היא אוספת את כל הנתונים (`getAppData()`) ומייצאת קובץ JSON ל-Google Drive.
2. **התחברות:** המשתמש מתחבר (או נרשם) לחשבון Firebase החדש דרך טופס מייל/סיסמה בתוך `migrate.html` עצמו.
3. **ייבוא:** המשתמש מדביק/מעלה את קובץ ה-JSON, והכלי כותב את כל הנתונים (תבניות, סוגי מדידה, אימונים, מדידות) למבנה Firestore החדש, עם פס התקדמות, לוג הצלחות/שגיאות לכל רשומה, וטיפול בהמרת תאריכים (`DD/MM/YYYY` → `YYYY-MM-DD`).
- נגיש בפרודקשן דרך נתיב ייעודי `/migrate` (מוגדר ב-`firebase.json`).
- **אינו מתורגם (`t()`)** — כתוב בעברית קשיחה בלבד, ללא תמיכה באנגלית — סביר שמדובר בהחלטה מכוונת כי זהו כלי טכני חד-פעמי למשתמש אחד (בעל האפליקציה המקורית), לא חלק מהמוצר הרב-לשוני.
