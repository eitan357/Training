# מסמכי מוצר — Training Diary

תיעוד מוצרי מלא של האפליקציה, שנכתב מתוך קריאה שיטתית ומלאה של כל בסיס הקוד (Frontend + Backend), קבצי הבדיקות האוטומטיות (כמקור לדרישות NFR), ותוכניות הפיתוח הקיימות. כל מסמך מכסה עמוד אחד או נושא-רוחב אחד, כולל: מטרת הפיצ'ר, פירוט כל אלמנט ב-UI, לוגיקת ה-Backend/מודל הנתונים, כללי עסק ומקרי קצה, והערות מוצריות (חוסרי-עקביות, פערים, סיכונים) שעלו תוך כדי הסקירה.

**התחילו כאן:** [`00-overview.md`](./00-overview.md) — סקירה כללית, ארכיטקטורה, ועקרונות מוצריים חוצי-אפליקציה.

## עקרונות עבודה עם המסמכים הללו

- כל מסמך מצטט את מיקום הקוד המדויק (שם קובץ + טווח שורות בקירוב) כדי שניתן יהיה לאמת/לעדכן בקלות כשהקוד משתנה.
- הערות המסומנות **"הערה מוצרית"** מציינות חוסרי-עקביות או החלטות עיצוב סמויות שכדאי שמנהל/ת מוצר יהיו מודעים אליהן (למשל: מחיקה קבוצתית ללא אישור, לעומת מחיקה בודדת עם אישור כפול).
- המסמכים מתעדים את **המצב הקיים בפועל** (reverse-engineered PRD), לא רשימת דרישות עתידיות — כל "פער" או "מחוץ לתחום" מצוין במפורש ככזה.
- בכל פעם שהקוד משתנה באופן משמעותי, יש לעדכן את המסמך הרלוונטי ולציין זאת (אין כרגע תהליך אוטומטי לזיהוי סטייה בין המסמכים לקוד בפועל).
