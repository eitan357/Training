# עמוד: הגדרות (Settings)

**קובץ מקור:** `public/index.html` — `#sec-settings` (שורות ~1144–1239), לוגיקת JS: "SETTINGS UI", "RUNNING SETTINGS" (חלקים), "THEME" (שורות ~1362–1418).

## מטרת העמוד ונגישות

עמוד ריכוזי לכל ההגדרות וההעדפות. **אינו חלק מהניווט התחתון** — נגיש אך ורק דרך אייקון גלגל שיניים (⚙) בפינת הסרגל העליון בכל אחד מעמודי התוכן (כוח, טיימר, מדידות/אירובי, היסטוריה). כפתור "← חזרה" קורא ל-`history.back()` — חלק ממנגנון ניווט מאוחד המבוסס על מחסנית history אמיתית (לא משתנה יחיד), כך שרצף ניווט מרובה-שלבים (למשל טיימר → הגדרות → עריכת תוכנית → הגדרות → חזרה) מחזיר תמיד לעמוד הנכון, ללא קשר לכמה מסכי-ביניים נפתחו בדרך. פירוט ב-`docs/superpowers/specs/2026-08-30-unified-navigation-history-design.md`.

## מבנה: קבוצות הגדרות

### קבוצה 1: עריכה
שלושה פריטי ניווט (לא הגדרות בעצמן, אלא קישורים למסכי עריכה מפורטים במסמכים נפרדים), **מוצגים תמיד לכל המשתמשים** ללא תלות בהרשאה כלשהי:
- **"לעריכת תוכנית אימוני כוח"** → `03-workout-template-editor.md`.
- **"לעריכת תוכנית אימוני אירובי"** (`openCardioEdit`) → מנווט ל-`/settings/cardio-plan`, פותח את עורך התבניות בתוך עמוד האירובי עצמו (`#cardioEditPanel`) — ראו "עורך תבניות אירובי" ב-`07-running-cardio.md`. השורה מוצגת גם אם הפיצ'ר האירובי כבוי (קבוצה 3 למטה); הניווט בפועל עדיין תלוי במתג "הצג עמוד אירובי" — ראו שם.
- **"עריכת סוגי מדידות"** → פרק "עורך סוגי מדידה" ב-`06-measurements.md`.

### קבוצה 2: פרופיל
- **שם תצוגה** (`displayNameInput`, `saveDisplayName`) — טקסט חופשי המוצג בכל סרגל עליון בכל עמודי האפליקציה (במקום כתובת המייל).
  - **שמירה מקומית:** בלחיצת "שמור", השם שמור מיידית ב-`localStorage` (ממותג לפי `uid`), הסרגל העליון מתעדכן אוטומטית, והודעת הצלחה מופיעה ("✓ שם תצוגה עודכן").
  - **סנכרון ל-Firestore:** ה-`saveDisplayName` מעלה את השם ל-Firestore (`users/{uid}/config/profile`, `merge: true`) בדרך fire-and-forget — אם הסנכרון נכשל (למשל ללא חיבור רשת), השגיאה **לא** מוצגת למשתמש. במקום זה, הכישלון נרשם ב-`localStorage` תחת `displayNamePending_<uid>`, והסנכרון יחזור על עצמו בשקט בפעם הבאה שהאפליקציה מדברת כבר ל-Firestore לכל סיבה אחרת:
    - בעקבות `reloadAppData()` (שמתבצע לאחר כל שמירה ידנית של מידע כלשהו, כמו שמירת תרגול או שינוי הגדרה)
    - בטיימר הטיוטה האוטומטי (כל 30 שניות כאשר משתמש עורך טיוטה)
  - **מה בדיוק נשמר בדגל (תוקן 2026-09-10):** `displayNamePending_<uid>` מחזיק את **השם עצמו** שנכשל בסנכרון, לא ערך בוליאני. קודם לכן הוא החזיק `'1'`, והניסיון-החוזר קרא מה-`displayName_<uid>` המשותף — אבל `loadAllData()` דורס את המפתח הזה בערך מהשרת בכל טעינה, ולכן משתמש ששינה שם במצב לא-מקוון היה מקבל את השם **הישן** מסונכרן חזרה, והשינוי שלו נעלם בשקט. בנוסף, הניסיון-החוזר מחזיר את השם הממתין ל-`displayName_<uid>` ולסרגל העליון, כדי שלא יהבהב הערך הישן. מחרוזת ריקה היא ערך ממתין לגיטימי (משתמש שמחק את שמו במצב לא-מקוון), ולכן הבדיקה היא `!== null` ולא בדיקת truthiness.
  - המוטיבציה: שם תצוגה הוא פרט נמוך-סיכון; אין צורך להטריד את המשתמש בשגיאות סנכרון זמניות. ראו `10-offline-and-sync-architecture.md` לדיון כללי על דפוסי סנכרון עם ניסיון מחדש.
  - אם משאירים את השדה ריק ושומרים, השם נמחק מ-`localStorage` ומ-Firestore, וחוזרים להצגת כתובת המייל בסרגל העליון.

### קבוצה 3: מראה
- **ערכת נושא** — שלושה כפתורים: בהיר / כהה / אוטומטי. "אוטומטי" עוקב אחרי הגדרת מערכת ההפעלה (`prefers-color-scheme`) בזמן אמת. הבחירה נשמרת רק ב-`localStorage` (**לא מסונכרן ל-Firestore** — הגדרה זו היא per-device, לא per-user).
- **שפה** — כפתורים דינמיים הנבנים מתוך `LANGUAGES` ב-`translations.js` (כרגע עברית/אנגלית בלבד). שינוי שפה מיידי, ללא רענון דף, כולל היפוך כיוון הדף (RTL↔LTR). מפורט ב-`09-i18n-and-theming.md`. נשמר רק ב-`localStorage`.
- **"הצג עמוד אירובי" (Feature Gate Toggle)** — מתג פשוט (`runningEnabledToggle`), **מוצג לכל המשתמשים ללא יוצא מן הכלל**. אין יותר רשימת מיילים קשיחה בקוד — הגישה לפיצ'ר האירובי (גם עמוד היום-יומי וגם עורך התבניות) תלויה אך ורק בערך הבוליאני הזה (`_isRunningAllowed()` בודק רק אותו). כבוי כברירת מחדל. מפורט מלא ב-`07-running-cardio.md`. **שגיאות בשמירה** (כשל כתיבה ל-Firestore) מוצגות כ-`t('error.save') + firestoreErrMsg(err)` — הודעה מתורגמת בעברית או באנגלית תלוי בשפת המשתמש, כולל שם שגיאת Firestore מותאם.

### קבוצה 4: טיימר
- **"צליל בסוף טיימר"** (מתג) — קובע האם ישמע ביפ כשהטיימר מגיע ל-0. נשמר רק ב-`localStorage` (`timerSound`). ברירת מחדל: מופעל.

### פעולה: יציאה
- כפתור "יציאה" (`handleLogout`) בתחתית העמוד, בעיצוב מובחן (מסגרת אדומה) כדי לסמן פעולה משמעותית — אך **ללא דיאלוג אישור** (התנתקות מיידית בלחיצה אחת). מפורט מעברי המצב ב-`01-auth-onboarding.md`.

## חלוקת אחסון: מה נשמר איפה (חשוב להבנת המוצר)

| הגדרה | `localStorage` (מכשיר) | Firestore (חשבון) |
|---|---|---|
| שם תצוגה | ✓ `displayName_<uid>` | ✓ |
| שם תצוגה שממתין לסנכרון | ✓ `displayNamePending_<uid>` | ✗ (מקומי בלבד, נמחק ברגע שהסנכרון מצליח) |
| ערכת נושא | ✓ | ✗ |
| שפה | ✓ | ✗ |
| הפעלת עמוד אירובי | ✓ (קאש) | ✓ (מקור אמת) |
| צליל טיימר | ✓ | ✗ |

**המשמעות המוצרית:** משתמש שמתחבר ממכשיר חדש יראה שוב את ערכת הנושא/שפה/צליל בברירת המחדל של המכשיר (לא מה שהגדיר במכשיר אחר), אך שם התצוגה שלו ומצב הרשאת האירובי כן יעברו אוטומטית. זו החלטת מוצר סמויה שכדאי להיות מודעים לה — לא מתועד היום למשתמש בממשק.

## אתחול המסך (`initSettingsUI`)

בכל כניסה לעמוד ההגדרות: מסונכרנים מחדש כפתורי ערכת הנושא הפעילה, מצב מתג צליל הטיימר, בורר השפה, ערך שם התצוגה מה-`localStorage`, ומצב מתג "הצג עמוד אירובי" מסונכרן מול הערך העדכני ביותר (כדי שהמצב תמיד תואם, גם אם השתנה ממכשיר אחר מאז הטעינה הראשונית).
