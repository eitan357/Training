# עמוד: אירובי / ריצה (Running / Cardio) — פיצ'ר מוגבל-גישה

**קובץ מקור:** `public/index.html` — `#sec-running` (שורות ~1033–1143), לוגיקת JS תחת "RUNNING STATE" / "RUNNING DATA LAYER" / "RUNNING CALCULATIONS" / "RUNNING UI" / "RUNNING ADD WORKOUT" / "RUNNING HISTORY" (שורות ~1453–1958). מסמך עיצוב מקורי: `docs/superpowers/specs/2026-07-16-running-integration-design.md`.

## מטרת הפיצ'ר ומגבלת הגישה (Feature Gate)

מעקב אימוני אירובי (ריצה, אליפטיקל) — נפרד לגמרי ממערך אימוני הכוח. הפיצ'ר **מוגבל בקוד לרשימת מיילים קשיחה**: `['eitan357@gmail.com', 'test@gmail.com']` (הכתובת השנייה משמשת ל-QA/בדיקות אוטומטיות). כל משתמש אחר לעולם לא רואה את המתג המפעיל את זה בהגדרות ולא את העמוד עצמו.

**מנגנון ההפעלה בפועל:** גם למשתמשים ברשימת ההיתר, הפיצ'ר **כבוי כברירת מחדל** ודורש הפעלה ידנית דרך מתג בהגדרות ("הצג עמוד אירובי", ראו `08-settings.md`). המצב נשמר ב-Firestore (`users/{uid}/config/settings` → `runningEnabled: boolean`) וגם מקומית (`localStorage`) לטעינה מיידית.

**השפעה על הניווט התחתון:** כשהפיצ'ר מופעל, טאב "מדידות" **נעלם ומוחלף** בטאב "אירובי" באותו מיקום בדיוק — לא נוספת שורת טאב חמישית. כלומר משתמש עם הפיצ'ר מופעל לא יכול לגשת גם למדידות וגם לאירובי בו-זמנית דרך הניווט התחתון (עמוד המדידות עדיין קיים ב-DOM ונגיש טכנית, אך לא דרך ניווט רגיל).

## מבנה: שלוש תת-תצוגות (Sub-Views) בתוך עמוד אחד

הניווט הפנימי מתבצע דרך `history.pushState` (לא `showSection` הרגיל) — כך שכפתור "חזרה" של הדפדפן/מכשיר (`popstate`) עובד באופן טבעי בתוך תת-התצוגות.

### 1. דשבורד (`run-view-dashboard`) — ברירת מחדל
- שני כפתורים עליונים: "+ הוסף אימון" ו"היסטוריה".
- **תג "רצף שבועי" (Streak):** מספר גדול המציין כמה שבועות רצופים (לפי שבוע קלנדרי ISO-כמעט, מחושב לפי `getFullYear` + מספר שבוע יחסי ל-4 בינואר) יש בהם לפחות אימון אחד, נספר אחורה מהיום.
- **כרטיס "שיאים אישיים" (PRs):** מרחק מירבי (ק"מ), קצב מהיר ביותר (min/km, הנמוך ביותר מבין הרשומות עם קצב תקין), דופק נמוך ביותר שנרשם.
- **כרטיס "אימון אחרון":** תאריך, סוג, מרחק, משך, קצב.
- **כרטיס גרפים:** 5 גרפי קו (Chart.js, ייטענו רק אם יש נתונים לאותו מדד) — מרחק (כחול), דופק ממוצע (אדום-חום), קצב (ירוק), קלוריות (כתום), צעדים לדקה (סגול). בורר טווח זמן: חודש / שנה (ברירת מחדל) / הכל, המסנן את כל 5 הגרפים יחד.

### 2. הוספת אימון (`run-view-add`) — תהליך תלת-שלבי
- **שלב 1 — בחירת סוג אימון:** רשימת כפתורים לפי `runWorkoutTypes` (נטענים מ-Firestore; באתחול ראשון למשתמש נוצרים אוטומטית שני סוגים: "Running" ו-"Elliptical", לפי סדר `order`).
  - בחירת "Elliptical" מובילה לשלב 2 (OCR); בחירת סוג אחר מדלגת ישירות לשלב 3.
- **שלב 2 — OCR מתמונת מסך (רק לאליפטיקל):** המשתמש מצלם/בוחר תמונה ממכשיר האימון (מסך התצוגה של המכונה). הספרייה **Tesseract.js נטענת רק בשלב זה** (lazy load מ-CDN, כדי לא להאט את טעינת האפליקציה הראשית עבור משתמשים שלא נוגעים בפיצ'ר). המערכת מנתחת את הטקסט שזוהה (`parseOcrText`) בעזרת מגוון תבניות רגקס וקרבה-למילת-מפתח (`nearKeyword`) כדי לחלץ: מרחק, משך (תומך בפורמט `hh:mm:ss` או `mm:ss`), קלוריות, קצב צעדים לדקה, ודופק ממוצע — גם באנגלית וגם בעברית, וגם עם פסיק עשרוני אירופאי (`5,32` → `5.32`).
    - כישלון OCR מציג הודעת שגיאה עם אפשרות "הכנס ידנית" תמיד זמינה כ-fallback.
- **שלב 3 — טופס סקירה/עריכה:** שדות תאריך* / מרחק (ק"מ)* / משך (דקות)* (שלושתם חובה) + קלוריות / צעדים-לדקה / דופק ממוצע / "הרגשתי עייפות" (מתג) / הערות (כולם אופציונליים). אם הגיעו משלב OCR, השדות ממולאים מראש אך ניתנים לעריכה חופשית.
  - ולידציה: שלושת השדות החובה לא יכולים להיות ריקים ("יש למלא תאריך, מרחק ומשך"), וגם מרחק/משך חייבים להיות גדולים מ-0 ("מרחק ומשך חייבים להיות גדולים מ-0").
  - שמירה מחשבת `paceMinPerKm = duration / distance` בצד הלקוח ושומרת אותו יחד עם שאר השדות למסמך חדש (`users/{uid}/runWorkouts`), ואז מנווטת בחזרה לדשבורד האירובי (`navigateTo('/running')`).

**הערה מוצרית (עודכן):** כל שלב באשף (בחירת סוג / OCR / טופס) נדחף כרשומת history נפרדת. לחיצה על "חזרה" (בממשק, בדפדפן, או בכפתור הפיזי באפליקציית האנדרואיד) חוזרת שלב-שלב באשף, ולא קופצת ישירות לדשבורד — תיקון להתנהגות קודמת שבה חזרה באמצע האשף דילגה תמיד לדשבורד.

### 3. היסטוריה (`run-view-history`)
- רשימה כרונולוגית הפוכה (החדש ביותר ראשון) — **ללא קיבוץ חודשי** (בשונה מהיסטוריית אימוני כוח/מדידות).
- כל שורה: תאריך (+ אייקון עייפות אם סומן), סוג אימון, מרחק, קצב. לחיצה מרחיבה שורה עם משך/קלוריות/דופק/צעדים/הערות.
- **אין עריכה ואין מחיקה** של אימוני ריצה בהיסטוריה בגרסה הנוכחית — פעולות אלו אינן ממומשות לישות `runWorkouts` (בשונה מאימוני כוח ומדידות).

## מודל נתונים (Backend)

- **`users/{uid}/runWorkoutTypes`** — `{ name: string, order: number }`. נוצר אוטומטית עם "Running" (order 0) ו-"Elliptical" (order 1) בביקור הראשון בעמוד. **אין ממשק לניהול הסוגים האלה** (הוספה/מחיקה/שינוי שם) — מוגדר כ"מחוץ לתחום" במפורש במסמך העיצוב המקורי.
- **`users/{uid}/runWorkouts`** — שדות: `date` (YYYY-MM-DD), `workoutTypeId`, `distanceKm`, `durationMinutes`, `paceMinPerKm` (מחושב), `calories`/`avgStridesPerMin`/`avgHeartRate` (nullable), `feltTired` (boolean), `notes` (nullable), `createdAt`.

## ביצועים: טעינה מוקדמת ברקע (Prefetch)

- ברגע שהפיצ'ר מזוהה כמופעל (`loadRunningEnabled`), האפליקציה **מתחילה לטעון את נתוני הריצה ברקע מיד**, עוד לפני שהמשתמש בכלל ניגש לעמוד — כך שכשהוא כן לוחץ על טאב "אירובי", הדשבורד כבר מוכן ללא זמן המתנה נראה לעין. הבטחה (`_runDataPromise`) מונעת טעינה כפולה אם המשתמש נכנס לעמוד לפני שהטעינה ברקע הסתיימה.

## תחומים המוגדרים במפורש כמחוץ לתחום (Out of Scope, לפי מסמך העיצוב)

- ניהול סוגי אימון אירובי (הוספה/מחיקה) בממשק.
- שיתוף חברתי / ייצוא נתונים.
- התראות/תזכורות לאימון.
